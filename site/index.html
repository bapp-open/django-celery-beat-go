gobeat

A small Go service that replaces the celery beat process for Django projects. Your workers and tasks stay exactly as they are.

Quick start

pip install django-gobeat
# settings.py
INSTALLED_APPS += ["django_gobeat"]

# myapp/cron.py — discovered automatically, like models.py
from django_gobeat import CronInterface, crontab

class NightlyCleanup(CronInterface):
    schedule = crontab(minute=0, hour=4)
    timezone = "Europe/Bucharest"

    def run(self):          # executed by a Celery worker
        ...
python manage.py migrate        # also syncs the jobs for gobeat
docker run -e DATABASE_URL=postgres://user:pass@db/app \
    ghcr.io/bapp-open/django-celery-beat-go

What it does

Jobs in cron.py Declare periodic jobs as classes in each app; no django-celery-beat required.
django-celery-beat compatible Optional: existing PeriodicTask rows and the admin keep working, with identical behaviour.
Claim before publish Each run is claimed in Postgres first and journaled until the broker confirms it.
One active replica A second instance stands by on a Postgres advisory lock and takes over on failure.
Redis and RabbitMQ Messages are byte-identical to what Celery itself publishes.
Shadow mode Run it beside Python beat in dry-run and diff the two dispatch logs before switching.

What it does not do

  • Databases other than PostgreSQL; brokers other than Redis and RabbitMQ.
  • Celery versions other than the latest stable (5.7.x) — it refuses to start rather than guess.
  • Non-JSON task serializers (pickle, yaml, msgpack) and solar schedules.
  • Anything that needs your Python code at publish time: publish signal handlers (Sentry/OpenTelemetry header injection), task-sent events, argument-dependent routers.
  • Running tasks or storing results — it only schedules and sends them.

Unsupported input is reported with an error naming the task and skipped; it is never approximated. The full list is in the README.
